# 04. Testing, Validation & Verification

## Automated Testing Strategy

The repository relies on continuous integration (CI) via GitHub Actions rather than traditional local unit test runners (e.g. Jest or Mocha).

### CI HTML Proofing (`proof-html.yml`)

The primary automated quality check is executed through the `anishathalye/proof-html@v1.1.0` GitHub Action.

#### What is Tested:
- **HTML Syntax & Validity**: Validates standard HTML markup across files in the directory `./`.
- **Internal / External Links**: Confirms that referenced internal relative links and anchors exist and that external URLs do not return HTTP 404/broken errors.
- **Image Attributes**: Checks that image tags contain appropriate source paths and attributes (e.g., `alt` tags).

### Current Execution Results & Characteristics

- Since `index.html` only contains `<h1>Welcome to the website generated by my demo repository</h1>`, the HTML proofing suite evaluates this single document.
- The repository does not include unit tests, end-to-end browser tests (e.g., Playwright / Cypress), or linters (e.g., HTMLHint, ESLint, Stylelint).

## Manual Verification Steps

To manually verify the HTML locally before pushing:
1. Validate HTML structure using an HTML validator tool:
   ```bash
   npx html-validator-cli --file=index.html
   ```
2. Verify package syntax:
   ```bash
   node -e "JSON.parse(require('fs').readFileSync('package.json'))"
   ```
